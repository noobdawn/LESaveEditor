# 独立世界编辑与游戏模式

首页提供三个区块：配装 URL、过滤器 XML 导入、世界编辑。第三入口不请求 Build，直接进入“上传存档 → 世界编辑 → 修改预览”。原配装同步和过滤器流程保留；世界入口不会同步角色等级、职业、装备、背包、技能或天赋，也不会继承上次会话的战役／终局速通选项。

## 文件与模式

世界入口接受一名角色、多个同赛季仓库、仓库页及一份 `Epoch_Local_Global_Data_Beta` 索引，可分批补传。每个文件不超过 32 MiB，最多 256 个文件，总文本量不超过 256 MiB。不同赛季、不同已识别账户、重复原生文件名、身份不匹配的文件整批拒绝。原 Build 同步入口仍限制为一个角色和可选的一个匹配仓库。

普通／专家与单角色挑战分别选择。当前版本原生 `CharacterData.GetLifeState`（RVA `0x1C4A8A0`）使用 `hardcore` 和 `deaths`；有效专家要求 `hardcore=true` 且 `deaths=0`，不能只读取 `died`。转入专家会明确清零死亡次数并清除 `died`，历史死亡成就对象保留。退出专家不删除死亡历史。

离线仓库选择由 `GlobalDataTracker.GetStashType`（`0x2869C90`）与 `Stash.MakeId`（`0x1C57570`）决定。当前赛季普通共享为 `STASH_CYCLE_<cycle>_0`，有效专家共享为 `_1`，单角色独立仓库为 `_2_<角色 id>`；单人挑战优先于专家。旧 cycle 0／1 使用 `STASH_<type>` 命名。已死亡专家正确匹配普通仓库，修复此前仅检查 `hardcore` 的错误。

## 分拆与合并

进入单人挑战时保留原共享仓库。目标独立仓库不存在时，玩家须确认新建并上传全局索引；工具生成空仓库、一个空仓库页及索引引用，角色装备和背包原样保留。新仓库的资源、阵营与仓库进度从空开始；角色阵营显示跟随目标仓库。索引或已载入仓库中已有同名目标时禁止覆盖，要求上传实际目标文件。

退出单人挑战可选择只切换到目标仓库，或合并独立仓库。合并需要源仓库、目标仓库（或确认新建）、全局索引和源仓库 `tabsv2` 中的全部页。工具执行：

- 金币、远古骨骸、词缀碎片、材料、钥匙与编织回响按身份累加到目标，清除源端对应资源，防止两端重复消费；溢出 int32 上限或未知编码拒绝处理。
- 保留源仓库页的原文件名和全部物品字节，不向目标页重新排格、不覆盖目标页。源仓库归档为只取出，通过目标 `retiredStashes`／`retiredStashesData` 关联，全局索引移除源的顶层引用。
- 已解锁祝福、世界线进度、地下城层级与可选章节取并集；同一任务优先保留当前目录确认的完成记录，冲突中的未知进度仍留在归档源中。最高腐化保留较高值。
- 阵营专属数据和共鸣不猜测合并身份，保留在源仓库。源阵营 ID 写入 `unmergedFactions`，供游戏处理待合并阵营。界面和预览明确说明这部分需要进入游戏处理，不能将资源合并等同于全部阵营数据已合并。

归档关联依据同构建 `GlobalDataTracker.RetireStash`（`0x286B070`）及 `CharacterChallengeSetting.LoadStashAndProcessMerge.MoveNext`（`0x15B7D40`）。已有归档目标不能直接重新启用；嵌套归档源也拒绝自动合并，以免重复资源或覆盖旧物品页。当前不提供跨赛季迁移或重新启用历史归档仓库。

## 状态与验证

[modes.js](../web/src/core/modes.js) 提供模式识别、仓库选择、文件验证和跨文件事务。[workflow.js](../web/src/core/workflow.js) 的 `route='world'` 跳过配装读取；`modeDraft` 与 `previewMode()` 基于原始上传文档生成预览，`prepareReview()` 先应用模式，再应用目标角色／仓库的世界编辑。改变模式会清除旧世界草稿和下载确认；补传文件后重新生成预览。每次复核从原始数据重算，不累计资源。

新建文件与修改文件都逐个下载，文件名保持游戏原生名称。全局索引、新仓库和新仓库页需一并放回；只下载角色无法完成仓库切换。原始文件不会被网页直接写入。

当前本地完整测试 234 项：228 通过、6 个可选私人检查跳过、0 失败。显式提供参考 `_7` 角色、普通共享仓库和全局索引的专项测试十项通过，包含分拆后再合并的往返，装备字节和原资源总量保持不变。源文件只读。自动验证覆盖模式／死亡判定、旧周期命名、无需网络的入口、多个仓库、补传文件、失败原子性、新文件下载、资源累计、重复预览、uint64 保留、账户／赛季隔离与归档保护。

2026 年 10 月 18 日，用户反馈本地验收无问题，并确认提交与推送本次修改。上述自动测试未直接覆盖游戏内所有仓库载入、只取出物品页、阵营待合并操作与资源消耗场景。
