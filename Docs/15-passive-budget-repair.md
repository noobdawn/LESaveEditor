# 同步预算补齐

2026 年 10 月 18 日，修复配装同步对已获得但未写入点数记录的被动点漏算。

## 问题与修复

旧逻辑仅使用存档的已分配加未分配点数，再增加等级差带来的点数。已完成任务奖励已满、点数记录为 0 的一级角色，同步到 100 级会仅计算 99 点；原本已到 100 级的同类存档则会被视为可用 0 点。

[planner.js](../web/src/core/planner.js) 在被动同步及仅变更等级的两条路径中，先取已记录预算与原等级应得点数的较大值，再应用等级变化：

```text
earned(level, rewards) = max(0, level - 2 + rewards)
base = max(已分配 + 未分配, earned(原等级, 已完成任务奖励))
budget = base + earned(目标等级, 已完成任务奖励) - earned(原等级, 已完成任务奖励)
```

任务奖励仍按原有任务完成判定计算，上限为 15。修复不把未完成任务视为完成，不削减已有超额预算，也不反复累加已经记录的点数。降级继续按应得点数差扣减；保留旧分配时若预算不足，仍拒绝操作。未同步被动且未变更等级的调用，以及独立世界编辑，不触发修复。

用户提供的角色文件只读验证通过：原始 100 级存档及受控一级副本分别在开启／关闭速通时执行两次同步，导出重读后均为 112 点已分配、1 点未分配，共 113 点。该验证采用仓库中的公开 om6w3Ypq 测试配装，不代表已取得用户原先使用的配装链接。原文件 SHA-256 前后一致，私人存档未加入仓库。
