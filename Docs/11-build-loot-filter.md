# Build 过滤器

[返回项目说明](../README.md)

过滤器从公开 Build 提取需求，不需要上传存档。存档同步流程、世界编辑与物品编码保持独立。

## 五步确认

1. 需求暗金：按身份选择暗金，套装单列，可搜索补充过渡目标。
2. 高价值词缀：从装备实际附加词缀初始化，可增删；神像条目按形状选择兼容前后缀，导出时合并为全部神像共享的词缀集合。
3. 有效词缀：通用生命、耐伤、护盾、属性、抗性、护甲、防御与功能词缀默认勾选。高价值词缀同样有效，在合并集合中只计一次。
4. 隐藏类型：逐项或按装备家族选择装备类型，按职业或逐底材选择神像，也可隐藏整个神像形状。默认不隐藏任何类型。
5. 分组与导出：调整显示／隐藏、颜色与强调，预览并下载原生 XML。

## 四类普通装备

令 H 为高价值词缀，U 为高价值与其余有效词缀的并集。仅统计实际存在的所选词缀，不给无效词缀或空槽扣分。

| 优先级 | 固定分组 | 条件 |
| --- | --- | --- |
| 1 | 核心词缀崇高装备 | 崇高，至少一条 H 达到 T6 |
| 2 | 有效词缀崇高装备 | 崇高，至少一条 U 达到 T6，且至少三条 U |
| 3 | 考虑打造装备 | 至少两条 U 达到 T5，且至少一条 H 达到 T5 |
| 4 | 开荒过渡装备 | 至少一条 H，且至少三条 U，不限层级 |

T6/T7 为同一档，T8 也满足 T6 条件；T5 条件包含更高层级；T4 及以下由不限层级规则处理。高优先级先匹配，隐藏同样终止匹配。四类分组不能添加、删除、改名或配置门槛。未匹配的普通、魔法、稀有与崇高装备使用一条默认隐藏的兜底，不作为第五个可配置装备类别。

每类仅生成一条原生 Rule，使用包含装备类型 0–24 的一个 SubTypeCondition。多个词缀 ID 共享 AffixCondition，多个条件取 AND。空词缀池和原生编辑器会钳制的不可满足计数不会生成宽泛规则。典型公开 Build 的四类装备为四条，总计 19 条规则；再隐藏双手近战武器及非本职业神像时为 21 条。

## 隐藏装备与神像

匹配顺序为暗金／套装分组 → 所选类型隐藏 → 四类普通装备、装备兜底及神像需求。暗金和套装遵循各自分组的显示／隐藏设置；普通、魔法、稀有与崇高装备以及普通神像命中所选类型即隐藏，即使满足四类装备或神像需求。装备类型隐藏限定普通、魔法、稀有与崇高稀有度。神像没有装备稀有度，显示、隐藏和兜底均只使用类型、职业需求和所需词缀条件。装备类型与神像形状分别合并；完整职业选择使用全部九种神像类型与一个 ClassCondition 合并为一条规则。只有零散底材选择才按形状分别生成单类型规则，再填写 subTypes；原生多类型条件不使用精确 subTypes。整形状已隐藏时省略重复底材规则。资源和祭坛不在此页的选择范围内。

“隐藏其他职业神像”读取当前 Build 的职业与目录 classRequirement 位标记：野蛮人 1、法师 2、哨卫 4、侍祭 8、游侠 16；Build 职业索引为 0–4。普通、异端与预兆底材使用同一判定，不按名字猜测。法师会选择其他职业的 48 个底材，保留法师 12 个及通用 13 个；导出只生成一条“隐藏非本职业神像”，职业 req 为 Primalist Sentinel Acolyte Rogue。取消任一底材后，该职业恢复精确底材规则，避免过度隐藏。初始没有自动排除双手武器或任何神像。

## 身份、特殊词缀与安全兜底

需求分析读取普通词缀、封印、腐化与原初附加字段；固有 ir/ur 不加入价值池。暗金 fixed variant 根据 game-item-data.json 的 specificAffixIds 归入 inherentAffixes；同一腐化词缀在其他装备上的真实附加仍可有效。真实原初词缀需要 T8。封印等额外词缀参与有效数量统计。

未解析目标或版本不匹配会把其他装备、其他神像兜底改为显示，并阻止严格兜底隐藏。用户明确选择的类型隐藏仍按其选择执行。暗金相对稀有度基于随机池 rerollChance，不代表 Boss 掉率或市场价格。需求身份、神像配对、资源和祭坛的规则保持各自范围。

切换阶段、语言和返回同一 Build 保留草稿；导入另一 Build 重建草稿。浏览器仅持久保存语言偏好；构造设置随导出的 XML 保存。schemaVersion 为 3，四类规则不再使用计分编译器或近似结果。导出遵循原生 Order 顺序与 XML 转义，规则上限仍为 200。

## 验证

运行 npm test 和 npm run build。固定规则边界测试与独立 XML 条件解释器检查 T1–T8、有效数量、所有装备类型、额外词缀、隐藏优先级、精确神像底材、特殊暗金来源及资源隔离。交互测试覆盖五步切换、选择保持、固定分组和颜色预览。依赖锁检查在 npm ci 前执行，避免缺失版本的可选平台依赖进入构建。

原生依据：ItemFiltering.ClassCondition 的 DataMember 为 req（ClassRequirement 位标记）；Match RVA 0x1969670（本项目 1.5.2.1 构建）在 req 非零时要求物品职业需求非零且完全包含于所选位标记，通用神像不匹配。规则名称按原因区分“隐藏所选装备类型”“隐藏所选神像类型”“隐藏非本职业神像”“隐藏所选职业神像”和带形状的“隐藏所选神像底材”。

单有效、双有效词缀神像分别只生成一条 Rule，SubTypeCondition 同时选择全部九种神像类型，不限定子类型或稀有度。启用条目的词缀按 ID 去重后共享：双有效分别要求所选前缀和后缀各一条，单有效要求至少一条；词缀可在其他兼容形状上生效并重组。停用条目不贡献词缀，空池不生成宽泛规则，只有前缀或只有后缀时不生成双有效规则。双有效优先于单有效，类型隐藏仍在两者之前。

雕文、符文、碎片、钥匙与特殊材料及神像祭坛的默认颜色统一为青色（原生调色板 14），保留每组的显示和强调设置。用户仍可自行修改分组颜色。

## XML 设置恢复

XML 使用版本化 LESaveEditor-settings:v1 注释保存 UTF-8 JSON 的 Base64 编码，包含词缀与身份选择、神像条目、隐藏类型、完整分组样式、语言、名称、稀有度选项、原配装摘要和未解析目标保护。注释放在 rules 集合之外，不增加规则、条件或游戏字段。完整存档、完整 Build 数据与临时搜索状态不写入。

首页及过滤器页提供导入 XML；文件只在浏览器中读取，恢复草稿后进入分组与导出，可回到任何阶段修改，无需重新请求配装数据。非法文件、旧版无注释文件、未知设置版本或未知物品编号会明确报错，并保留当前草稿。保存和导入共用现有领域校验；XML 限制 2 MB，设置数据限制 256 KB，不执行注释内容。

保留网页下载的原文件。游戏或第三方工具重新保存 XML 可能移除注释；这类文件不能完整恢复构造设置。导入以保存的网页设置为准，游戏内另外修改的原生规则不会逆向合并。物品目录版本变化会显示提示并打开保守兜底。
